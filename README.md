# manual-gen

웹 시스템을 분석해 **사용자 매뉴얼(PPT·PDF)을 자동으로 만들어 주는** Claude Code skill.

소스코드에서 화면 목록을 뽑고, 실행 중인 시스템이 있으면 브라우저로 메뉴를 돌며
실제 스크린샷을 찍은 뒤, 국내 SI 매뉴얼 관행 형식으로 문서를 완성한다:

```
[화면 스크린샷 — 기능 위치에 붉은 테두리 + ①②③ 번호 배지]
[사진 3] 사용자 목록

① 아이디, 이름으로 검색할 수 있습니다.
② [등록]을 클릭하면 등록 화면으로 이동합니다.
③ [삭제] 클릭 시 확인 후 삭제됩니다.
※ 관리자 계정은 최소 1개 이상 필요합니다.
```

표지 → 목차 → 장 간지 → 화면별 설명 슬라이드 구조의 `.pptx`(필요하면 `.pdf`로 변환)가
프로젝트 폴더에 생성된다. 회사·조직이 지정한 매뉴얼 템플릿(pptx)이 있으면 그 표지·목차·
머리글 모양 그대로 만들 수 있다(6절).

---

## 1. 준비물

| 필요한 것 | 비고 |
|---|---|
| **Claude Code** (데스크톱 앱 또는 CLI) | 이 skill의 실행 환경 — https://claude.com/claude-code |
| **Claude 모델: Sonnet 이상 권장** | 문서의 형식·구조·검수는 검증 게이트가 모델과 무관하게 보장하고, 설명 문장도 화면 유형별 표준 문형을 따르게 해 모델 간 편차를 줄였다. 다만 **화면을 이해하고 기능을 파악하는 정확성은 모델 성능에 비례**하므로 — 모델이 좋을수록 결과가 정교해지며, 화면이 많거나(50+) 복잡한 시스템일수록 상위 모델(Opus 등)을 권한다 |
| **Python 3.10+** | 문서 생성·이미지 처리 스크립트용 — **없으면 skill 이 처음 실행할 때 설치 여부를 묻는다**(아래) |
| Chrome (권장) | 화면 캡처용 — 없으면 Edge/Whale 등으로 선택 가능 |

PDF 변환은 PowerPoint 또는 LibreOffice 를 쓴다(둘 중 하나만 있으면 된다).

**파이썬이 없거나 3.10 미만이면** skill 이 맨 처음에 알려 주고 설치 방법을 묻는다
(Windows — 동의 없이 설치하지 않는다):

| 선택 | 하는 일 |
|---|---|
| winget 으로 설치 (권장) | Python 3.12 를 **현재 사용자에게만** 설치(관리자 권한 불필요, Microsoft 공식 winget 원본). 설치하면 Python 라이선스·winget 원본 약관에 동의하게 된다. 설치가 끝나면 이어서 진행 |
| 직접 설치 | https://www.python.org/downloads/ 에서 받아 설치 — 설치 첫 화면에서 **"Add python.exe to PATH" 체크** 후, Claude Code 에서 새 대화로 다시 호출 |
| 중단 | 설치하지 않고 멈춘다 |

미리 확인해 보려면(파이썬 없이 동작):

```powershell
powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\.claude\skills\manual-gen\scripts\check_python.ps1"
```

> Windows 에서 `python` 을 쳤을 때 Microsoft Store 가 열리면 설치된 것이 아니라 Store 로
> 연결되는 바로가기다 — 이 경우도 '없음'으로 판정한다.

파이썬 패키지(python-pptx, Pillow, Playwright 등)는 **처음 실행할 때 skill이 스스로
점검해서 없는 것만 설치를 안내**하므로 미리 설치할 필요 없다.

## 3. 빠른 시작

```
cd C:\projects\대상프로젝트     ← ① 매뉴얼을 만들 프로젝트 폴더에서 Claude Code 실행
/manual-gen                    ← ② 호출 (또는 "이 시스템 관리자 매뉴얼 만들어줘")
```

이후 자동으로 진행된다:

1. **환경·프로젝트 분석** — 의존성 점검, 기술 스택·화면 목록·실행 URL·대상 독자를 추론
2. **확인 1회** — 추론 결과 표를 보여주며 "이대로 진행?"을 묻는다 (유일한 필수 질문)
3. **캡처** — 브라우저로 화면을 돌며 스크린샷 + 테두리·번호 배지 합성 (로그인이 필요하면
   이때 "브라우저 창에서 로그인해 주세요"라고 요청할 수 있다 — 비밀번호를 채팅에 입력하지 않는다)
4. **문서 생성** — 프로젝트 폴더에 `관리자매뉴얼_<시스템명>_<날짜>.pptx` 생성
   — 지원 형식은 **pptx 와 PDF** 뿐이며(Word 미지원), PDF 는 완성된 pptx 를 변환해 만든다
5. **검수 보고** — 캡처 못 한 화면(placeholder)·주의 사항을 정리해 알려준다

pptx 는 **세로 A4가 기본**(가로 16:9 선택 가능)이다. 모양은 둘 중 하나로 정한다:

- **회사 지정 템플릿**(있으면 먼저) — 템플릿의 표지·목차·머리글·글꼴·색 그대로(6절).
  한 번 쓴 템플릿은 등록돼, 다음부터 확인 표에 기본값으로 나온다
- **기본 테마 3종**(템플릿이 없을 때) — navy(기본) / forest / charcoal. 흰 바탕 + 가는 강조선 + 기하 도형
  표지, 글꼴은 Pretendard 가 설치돼 있으면 Pretendard(없으면 맑은 고딕)

어느 쪽이든 본문 규격은 같다: 모든 캡처는 같은 폭·검은 테두리로 들어가고, 세로로 긴
캡처는 여러 쪽으로 나뉘며, 한 쪽을 넘는 표는 행 단위로 나뉘어 쪽마다 머리글이 반복된다.
관리자·사용자 매뉴얼이 분리된 세트는 표지에 독자 구분이 표기된다. 이미지 없는 짧은
절은 한 슬라이드로 병합되고, 제목만 있는 그룹 절은 빈 슬라이드를 만들지 않는다 — 모두
확인 1회 표에서 조정할 수 있다.

### 자주 쓰는 호출

```
/manual-gen                                    # 폴더 자동 인식, 확인 1회
/manual-gen http://localhost:8080 관리자 pdf     # 대상·독자·형식을 인자로 지정(pptx|pdf)
/manual-gen http://localhost:8080 auto          # 질문 0회로 끝까지 자동(파이썬 설치는 예외 — 묻는다)
/manual-gen 템플릿은 C:\양식\매뉴얼템플릿.pptx    # 회사 템플릿으로(처음 한 번 — 이후 등록부에서 기본값)
/manual-gen 이어서                               # 중단된 작업 재개
```

### 실행 중 나올 수 있는 질문

| 질문 | 언제 | 하면 되는 것 |
|---|---|---|
| "이 설정으로 진행할까요?" (표 1개) | 매 실행 1회 (auto 제외) | 확인 또는 수정 항목 선택 |
| "브라우저 창에서 로그인해 주세요" | 자동 로그인이 안 될 때 | 뜨는 창에서 직접 로그인 → 완료 알림 |
| "만들 영역: 하나만/전부?" | 관리자/사용자 화면이 나뉜 시스템 | 선택 (전부 = 영역별 문서 생성) |
| "화면에 개인정보가 보입니다" | 운영 데이터 감지 시 | 블러 처리/진행 여부 선택 |

무개입으로 쓰려면: `auto` 인자 + 환경변수 로그인을 설정한다. 값이 셸 히스토리에
남지 않도록 **Read-Host 입력** 방식을 쓴다 (현재 터미널에서만 유효):

```powershell
$env:WUM_LOGIN_ID = Read-Host "아이디"; $env:WUM_LOGIN_PW = Read-Host "비밀번호"
```

> 값을 명령줄에 직접 쓰면(`$env:WUM_LOGIN_PW = "비밀번호"`) PSReadLine 히스토리
> (`%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt`)에
> **평문으로 남는다**. 이미 입력했다면 해당 파일에서 그 줄을 지울 것.

## 6. 회사 지정 템플릿으로 만들기 (템플릿 모드 — 권장 사용법)

회사·조직이 정해 준 매뉴얼 pptx 템플릿이 있으면 **그 모양 그대로** 만든다.
템플릿에서 가져오는 것과 skill 이 그리는 것이 나뉘어 있어, 슬라이드를 통째로 복제할 때
생기던 제목 겹침·목차 붕괴가 없다.

| 템플릿에서 가져온다 | skill 규격으로 그린다 |
|---|---|
| 표지(배경 그림·로고·글꼴·색), 목차 모양, 머리글·꼬리글·쪽 번호, 장·절 제목 상자, 본문 쪽 가로선·장식 | 캡처(같은 폭·검은 테두리·번호 배지), 설명 문단, 표(넘치면 쪽 나눔), 긴 캡처 분할, 규격 검사 |

### 6-1. 처음 한 번 — 템플릿 분석 요약 확인

템플릿마다 "어느 자리에 무엇을 채울지"를 자동 분석한다. 분석은 추정이므로 **처음 쓰는
템플릿은 요약을 한 번 확인**한다(실행 중 자동으로 보여 주고, 미리 볼 수도 있다):

```powershell
python "$env:USERPROFILE\.claude\skills\manual-gen\scripts\analyze_template.py" "C:\양식\매뉴얼템플릿.pptx"
```

요약에서 볼 것:

| 요약 줄 | 확인할 것 |
|---|---|
| `표지: 시스템명←… · 대상←… · 연도←…` | 시스템명·대상·연도·매뉴얼 구분이 템플릿의 알맞은 자리에 연결됐는지 |
| `그대로 두는 고정 텍스트` | **예시 회사명·예시 시스템명이 여기 있으면 안 된다** — 있다면 그 글상자는 교체되지 않고 결과에 남는다(6-5) |
| `잔존 감시` | 템플릿의 예시 문구가 목록에 있는지 — 결과에 남으면 생성이 멈춘다 |
| `본문 영역` · `표본 … 장식` | 본문이 머리·꼬리 선 사이에 오는지, 표본 쪽의 선·로고가 옮겨지는지 |

분석 결과는 `%USERPROFILE%\.claude\manual-gen\templates\` 에 저장되고(skill 저장소 밖),
같은 템플릿이면 다음부터 그대로 쓴다. **템플릿 파일은 읽기만 하고 수정하지 않는다.**
템플릿을 고치면 자동으로 다시 분석한다(파일 이름을 그대로 두면 다른 폴더로 옮겨도 알아본다).

### 6-2. 등록 — 한 번 쓰면 다음부터 기본값

처음에는 호출할 때 템플릿 경로를 준다:

```
/manual-gen http://localhost:8080 관리자 템플릿은 C:\양식\매뉴얼템플릿.pptx
```

생성에 성공하면 그 템플릿이 **등록부**(`%USERPROFILE%\.claude\manual-gen\templates.json`)에
파일 이름으로 등록되고, 첫 등록이면 **기본 템플릿**이 된다. 다음 실행부터는 경로를 주지
않아도 확인 표의 '모양' 줄에 기본 템플릿이 기본값으로 나온다. 등록된 템플릿이 있어도
**매번 확인 표에서 확인한 뒤 적용**한다(다른 템플릿·기본 테마로 바꿀 수 있다).

회사 템플릿이 여러 개면 미리 등록하고 기본을 정해 둘 수 있다:

```powershell
$R = "$env:USERPROFILE\.claude\skills\manual-gen\scripts\template_registry.py"
python $R add "C:\양식\매뉴얼템플릿_A.pptx" --default    # 등록 + 기본 지정(분석 요약 출력)
python $R add "C:\양식\매뉴얼템플릿_B.pptx"
python $R list                                          # * 표시가 기본 템플릿
python $R default 매뉴얼템플릿_B                          # 기본 바꾸기
python $R remove 매뉴얼템플릿_B                           # 등록 해제(파일은 그대로)
```

템플릿 파일을 다른 곳으로 옮겼으면 같은 이름으로 다시 `add` 하면 경로가 바뀐다
(`list` 에 '파일 없음'으로 표시된다).

### 6-3. 매번 — 표지 문구와 재생성

- 표지 문구는 확인 표에서 정한다 — **시스템명·대상(예: 관리자용)·버전·날짜**. 연도 자리가
  있는 템플릿은 날짜의 연도가 들어간다.
- 문구가 템플릿의 예시 글자보다 길면 자동으로 맞춘다: 대상 라벨처럼 배경이 있는 자리는
  배경을 넓히고, 제목 등은 글자를 줄인다(원래 크기의 60%까지). 그래도 넘치면 두 줄이 되며
  `경고: 템플릿 글자 자리` 로 알려 준다 — 이때는 표지용 시스템명을 짧게 정하면 된다.
- 원고를 고친 뒤 다시 뽑을 때는 "pptx만 재생성해줘" — 확인 표에서 정한 템플릿으로 다시
  만든다.

직접 빌드하려면(원고 `manual-work\manual-draft.md` 가 있을 때):

```powershell
python "$env:USERPROFILE\.claude\skills\manual-gen\scripts\build_pptx.py" `
  --draft manual-work\manual-draft.md --out 관리자매뉴얼_시스템명.pptx `
  --template "C:\양식\매뉴얼템플릿.pptx"
```

### 6-4. 결과 확인 — 이 메시지가 나오면 정상

- `템플릿 잔존 검사 통과 — 표본 문구 0건` — 템플릿의 예시 문구가 결과에 남지 않았다
- `자체 검증 통과` 와 검수 보고의 `ERROR 0건`
- `경고: 템플릿 글자 자리` 가 없을 것(있으면 6-3)

기본 테마와 다른 점: 장 간지 쪽이 없다(본문 머리의 장 제목이 장 구분을 맡는다). 템플릿
머리(장·절 제목 2단)가 높으면 쪽마다 본문 공간이 조금 줄어 나뉘는 쪽이 약간 늘 수 있다.
본문 내용은 기본 테마와 같다.

### 6-5. 템플릿이 갖춰야 할 것 / 지금의 한계

잘 맞는 템플릿 구조(회사 템플릿을 새로 만들거나 고칠 때 참고):

- 크기: 세로 A4(7.5x10.83in) 또는 가로 16:9
- 첫 장 = 표지. **시스템명 자리는 '제목 개체 틀(자리표시자)'** 로 둔다 — 일반 글상자에
  예시 이름을 써 두면 그 글자가 교체되지 않는다
- 목차 쪽 1장('목차' 또는 'CONTENTS' 글자, 'CHAPTER 01' 라벨 자리)
- 본문 표본 쪽 1장 — '01. 장 제목', '1.1 절 제목' 글상자가 있는 쪽. 이 상자 모양이 모든
  본문 쪽의 제목이 되고, 이 쪽에 그린 선·로고도 모든 본문 쪽에 옮겨진다
- 템플릿 글꼴은 **만드는 PC에 설치**돼 있어야 한다(PDF 에는 글꼴이 포함된다. pptx 를
  다른 PC에서 열면 그 PC에도 글꼴이 있어야 같은 모양으로 보인다)

지금의 한계:

- 자동 분석은 위 구조의 템플릿으로 검증했다. 구조가 다른 템플릿은 일부 자리를 못 찾을 수
  있으므로 6-1 요약 확인이 필수다. 분석이 실패하면(표본 쪽 없음·지원하지 않는 크기)
  `/manual-gen` 은 이를 알리고 기본 테마로 만든다(직접 빌드는 오류로 멈춘다).
- 표 높이를 넘치지 않게 넉넉히 잡기 때문에, 긴 표가 여러 쪽에 걸치면 쪽 아래에 여백이
  남는다. 표는 한 쪽에 담기는 크기가 가장 보기 좋다.
- 장 간지용 레이아웃은 쓰지 않는다.

## 7. 자주 겪는 문제

| 증상 | 원인·해결 |
|---|---|
| `/manual-gen`이 목록에 안 뜸 | 설치 후 **새 대화**를 열어야 인식된다 |
| 스크린샷에 테두리·배지가 없음 | 캡처를 건너뛰고 문서만 재생성한 경우 — "배지 적용해서 재생성" 지시 |
| 로그인 화면에서 멈춤 | 캡처용 브라우저 창에서 직접 로그인 후 "로그인했어"라고 알리면 이어서 진행 |
| 중단된 작업을 이어서 하고 싶음 | 같은 폴더에서 `/manual-gen 이어서` — inventory 기준으로 재개 |
| 원고는 그대로 두고 문서만 다시 뽑고 싶음 | "pptx만 재생성해줘" — 캡처 재사용, 수 초 소요 |
| 특정 화면이 placeholder(회색 상자)로 나옴 | 캡처 실패 화면 — 검수 보고의 사유 확인 후 해당 화면만 재캡처 지시 |
| 템플릿을 줬는데 기본 테마로 나옴 | 확인 표의 '모양'이 기본 테마였던 경우 — 템플릿 이름·경로를 지정해 재생성. 분석 실패 메시지가 있었다면 6-5 구조 확인 |
| 등록한 템플릿이 '파일 없음' | 템플릿 파일을 옮기거나 이름을 바꾼 경우 — `template_registry.py add <새 경로> --name <등록 이름>` (6-2) |
| "템플릿 표본 문구가 남았습니다"로 생성이 멈춤 | 템플릿의 예시 문구(예시 회사명 등)가 교체되지 않는 자리에 있다 — 6-1 요약의 '그대로 두는 고정 텍스트' 확인, 템플릿에서 그 글상자를 자리표시자로 바꾸거나 요약을 알려 주고 조정 요청 |
| 표지 제목·대상 라벨 글자가 작아짐 | 문구가 템플릿 자리보다 길어 자동으로 맞춘 것 — 표지용 문구를 짧게 정하면 원래 크기 |
| 템플릿 글꼴이 다른 글꼴로 보임 | 그 PC에 템플릿 글꼴이 설치돼 있지 않음 — 설치하거나 PDF 로 배포 |
| 표 쪽 아래 여백이 큼 | 표가 넘치지 않도록 높이를 넉넉히 잡은 결과(내용은 보존) — 표 행을 줄이면 한 쪽에 담긴다 |

## 8. 구성 (내부 구조)

```
SKILL.md                        # 워크플로 본체 (모드 판정 → 인터뷰 → 인벤토리 → 캡처 → 문서화 → 산출)
references/
├── source-analysis.md          # 스택 감지 표 + 스택별 화면/메뉴 추출 힌트 + 독자 영역 판별
├── live-capture.md             # 캡처 수단 의사결정 트리 + 배지·블러 절차 + 안전 수칙
├── manual-template.md          # 표준 목차·화면 문서화 포맷·표기 규약
└── output-formats.md           # pptx/PDF 규격 (고정 프레임·테두리·분할·검수)
scripts/
├── cdp_capture.py              # 캡처: 풀페이지·배지 좌표(--mark)·PII 블러(--redact-*)·
│                               #   에러 화면 감지·브라우저 검증·자동 로그인·재개(--skip-existing)
├── capture_browser.ps1         # OS 수준 창 캡처 (Windows, 의존성 없음)
├── annotate_screenshot.py      # 번호 배지+강조 테두리 합성
├── resize_images.py            # 문서 삽입 전 이미지 축소
├── draft_parser.py             # 원고 공용 파서
├── validate_draft.py           # 원고 사전 린터 — 구조 위반을 빌드 전에 차단
├── check_python.ps1            # 파이썬 확인·설치(동의 시 winget) — 파이썬 없이 도는 첫 점검
├── check_env.py                # 환경 점검(doctor) — 의존성·브라우저·가능 경로 확인
├── build_pptx.py               # 원고→PPTX (표지/목차/고정 프레임·테두리·분할·자체 검증)
├── template_mode.py            # 템플릿 모드 — 사용자 pptx 템플릿 분석·크롬 채우기·잔존 검사
├── analyze_template.py         # 템플릿 분석 요약·매니페스트 저장(템플릿 모드 사전 검토)
├── template_registry.py        # 템플릿 등록부 — 회사 템플릿 목록·기본 템플릿 지정
├── verify_pptx.py              # 산출 pptx 규격 검증 — 생성 경로 무관(서식 복제 경로 필수)
├── export_slides.ps1           # pptx→슬라이드별 PNG (렌더 검수용 — PowerPoint COM/soffice)
└── export_pdf.ps1              # pptx→PDF 변환 (최종 산출물 — PowerPoint COM/soffice)
tools/                          # 개발용 — 표 높이 추정 보정·실제 렌더 넘침 측정(tools/README.md)
```

템플릿 분석 결과(매니페스트)는 저장소가 아니라 사용자 폴더
`%USERPROFILE%\.claude\manual-gen\templates\` 에 저장된다(템플릿 경로·예시 문구가 담기므로).

주요 동작 원칙: 하이브리드 분석(소스+라이브, 한쪽만으로도 동작) · 독자 영역 자동
분리(영역별 별도 문서) · Chrome 최우선 캡처 · 무개입 로그인 3단계 · 어떤 환경에서든
동일 구조 산출(번들 빌더 기본 + 원고 린터 + 기계 검수).

## 9. 안전 원칙

- 라이브 순회는 **읽기 전용**: 저장/등록/수정/삭제/제출 버튼을 클릭하지 않음
- 비밀번호를 채팅으로 받지 않음: 세션 재사용/환경변수 기반 자동 로그인, 그 외에는
  사용자가 브라우저에서 직접 로그인 (자격 증명은 대화·저장소에 미노출)
- 화면에 개인정보(실명·연락처 등)가 보이면 캡처 전 확인, 캡처 시점 블러
  (`--redact-file`/`--redact-email` — PII를 CLI 인자로 받지 않으며, 가릴 문자열
  목록 파일은 `.gitignore` 영역인 `manual-work/`에 둔다)
