# 출력 형식별 변환 명세 (pptx / PDF)

manual-draft.md와 screenshots/를 최종 문서로 변환할 때의 요구 명세. 생성 경로:

1. **번들 빌더(기본)** — 어떤 환경(CLI/데스크톱)에서든 동일 구조를 보장하는 표준 경로.
   이 문서의 규격이 내장되어 있고, 원고 사전 검증(validate_draft)과 자체 검증
   (마크다운 잔재·항목 초과·배지 미사용)까지 수행한다. 생성기를 즉석에서 자작하지 않는다.
   ```
   python scripts/build_pptx.py --draft manual-work/manual-draft.md \
     --screenshots manual-work/screenshots --out ..\관리자매뉴얼_시스템명_20260714.pptx \
     [--title 시스템명] [--audience 관리자용] [--version 1.0] [--date 2026년 7월]
   ```
   의존성: python-pptx (미설치 시 종료 코드 2와 함께 설치 명령 안내 —
   강제 설치하지 않고 사용자에게 확인).
2. **전용 skill(특수 경로)** — 사용자가 **참고 템플릿 pptx를 제공해 서식 복제**가 필요한
   경우에만 `anthropic-skills:pptx`를 호출한다(번들 빌더가 못 하는 유일한 작업).
   이 명세를 호출 요구사항으로 전달하고, 산출 후 검수 절의 기계 검증을 동일 수행한다.
   **이 경로(전용 skill·프로젝트 자작 템플릿 빌더 포함)의 산출물은
   `python scripts/verify_pptx.py <pptx> --draft <원고>` 통과가 필수다** — 번들 내장
   규격(테두리·비율 유지·폭 균일·캡션·분할·placeholder)이 자동 적용되지 않는 경로라,
   파일 기반 독립 검증 없이는 규격 우회가 무경고로 납품된다. ERROR 는 생성기를 고쳐
   재생성한다(자작 빌더라면 번들 build_pptx 의 apply_picture_border·tile_tall_image
   등 공용 함수를 import 해 이식하는 것을 권장).
3. **최후 폴백**: 의존성 설치도 불가하면 manual-draft.md를 최종 산출물로 확정하고
   pandoc 등 변환 방법을 안내한다.

## 공통

- 산출 파일명: `<독자영역명>매뉴얼_<시스템명>_<YYYYMMDD>.pptx|pdf` — 독자 영역명을
  접두로 쓴다(예: `사용자매뉴얼_`, `관리자매뉴얼_`, `시스템관리자매뉴얼_`,
  `기관관리자매뉴얼_`). 독자 영역이 여러 개면 **영역마다 별도 파일**로 산출한다.
  **저장 위치는 대상 프로젝트 루트(또는 사용자 지정 경로)이며 manual-work/ 내부에
  두지 않는다** — 중간 산출물 공간은 .gitignore 대상이라 최종본이 함께 무시될 수
  있기 때문이다.
- 이미지는 `_annotated.png`가 있으면 그것을, 없으면 원본을 쓴다 (번들 빌더는 자동 우선).
- 사전 처리로 `python scripts/resize_images.py manual-work/screenshots --max-width 1400`을
  실행해 둔다 — 원본 해상도 그대로 넣으면 파일이 수십 MB로 커지기 때문이다.
- 원고의 인라인 마크업(`**`, 백틱)은 변환 시 실제 서식(굵게 등)으로 치환하거나 제거한다.
  변환 후 산출물 텍스트 추출본에 `**`, `![` 가 남아 있으면 안 된다.
- placeholder 블록은 회색 배경의 안내 상자로 렌더하되 **SCR-ID와 화면명만 표기**하고
  이미지 프레임과 동일한 크기·위치에 배치하며 `[사진 -] 화면명 (추후 삽입)` 캡션을
  동일 위치에 넣는다. 라우트·실패 사유 등 작업 메모는 넣지 않는다(inventory 전용).
  조용히 누락시키지 않는다.

## PDF 산출 명세

**지원 형식은 pptx 와 PDF 뿐이다(docx 미지원).** PDF 는 별도로 조판하지 않고
**완성·검증된 pptx 를 변환**해 만든다 — 레이아웃·규격(고정 프레임·테두리·타일 분할·
캡션·분할)이 pptx 빌더에 내장되어 있으므로 PDF 를 따로 만들면 그 규격이 전부 비껴간다.

```
powershell -ExecutionPolicy Bypass -File scripts/export_pdf.ps1 -Path <문서.pptx> [-Out <문서.pdf>]
```

- 변환 수단: PowerPoint COM(`SaveAs`, 글꼴·도형 재현이 가장 정확) → 없으면
  LibreOffice(`soffice --convert-to pdf`) 폴백. 둘 다 없으면 pptx 를 열어
  '다른 이름으로 저장 > PDF' 를 안내한다.
- **검증 순서**: pptx 를 먼저 `verify_pptx.py` 로 통과시킨 뒤 변환한다 — PDF 는
  파생물이라 별도 규격 검증기를 두지 않는다.
- 산출 파일명은 pptx 와 동일하고 확장자만 `.pdf`. pptx 도 함께 납품할지는 사용자 확인.

## pptx 생성 명세

### 공통 규격

- 슬라이드 크기: 세로 A4(7.5 x 10.833 in, 기본) / 가로 16:9(13.333 x 7.5 in) —
  `--orientation` 으로 선택한다. 글꼴은 Pretendard(설치돼 있으면, 없으면 맑은 고딕 —
  빌더 `--font auto|pretendard|malgun`). 전용 skill(서식 복제) 경로로
  요구사항을 전달할 때는 확정된 방향의 크기를 명시한다.
- 슬라이드 구성: ① 표지 → ② 목차 → ③ 장 간지(01/02/03...) → ④ 화면 슬라이드(본체) → 부록.
  이 기본 형태는 템플릿이 주어지지 않아도 동일하다(표지 + 목차 + 시스템 개요 + 화면·기능 설명 전개).
  템플릿 모드는 간지 없이 본문 머리의 장 제목이 장 구분을 맡는다(아래 '템플릿 모드').
- **방향**: 번들 빌더 `--orientation portrait|landscape` — 세로(A4, 기본)와
  가로(16:9)를 지원한다. 인터뷰(1-2 일괄 확인)에서 원하는 방향을 형식과 함께
  확인한다. 세로형은 모든 캡처를 상(이미지)/하(설명)으로 배치하고
  CONTENTS 를 1컬럼으로 구성하며, **이미지는 본문 폭을 가득 채우고 높이는 캡처
  비율을 따른다**(세로로 과하게 긴 캡처만 높이 상한에서 비율 유지 축소).
- **테마**: 번들 빌더 `--theme navy|forest|charcoal`(기본 navy) — 흰 바탕 위에서
  짙은색·강조색·옅은 틴트만 바뀐다(표지 도형, 절 번호·라벨, 머리·꼬리 가는 선, 표 머리).
  본문 텍스트·주의(※) 색은 공통이다. navy=네이비+로열블루, forest=딥그린+에메랄드,
  charcoal=차콜+코랄. 글자에 쓰는 강조색은 흰 바탕 명도비 4.5:1 이상으로 보정한다.
  **모양 결정 순서**(SKILL.md 1-1 의 9): ① 등록 템플릿(회사·조직 지정 — 기본 템플릿이
  기본값) → ② 사용자가 준 템플릿 경로 → ③ 템플릿이 없을 때 이 테마 3종. ①②는 아래
  **'템플릿 모드'**로 템플릿의 표지·목차·머리/꼬리·글꼴·색을 그대로 쓰고 본문은 번들
  규격으로 짓는다. 색만 가져오던 `--theme-from` 은 폐기 예정이다(테마 색이 Office
  기본값인 템플릿에서 추출이 실패한다 — 쓰면 경고). 템플릿 슬라이드의 **수작업 완전
  복제는 사용자가 명시 요구할 때만** 아래 '참고 템플릿 서식 복제(예외 경로)'로 진행한다.
- 화면 슬라이드는 **슬라이드 1장 = 화면 1개(inventory 기능 단위 1개)**가 원칙.
  번호별 설명이 6개를 넘으면 같은 제목으로 슬라이드를 나눈다(제목에 (1)/(2) 표기).
- **제목만 있는 부모 절(3단 번호의 그룹 제목)은 슬라이드를 만들지 않는다** —
  헤더만 있는 빈 장표가 생기기 때문이다. CONTENTS 에는 절 번호를 유지하되
  슬라이드 번호는 첫 하위 절 슬라이드를 가리킨다. (번들 빌더 내장)
- **개요 절 병합**: 이미지(캡처·placeholder)가 없는 짧은 절(시스템 소개·권한 체계·접속
  환경 등)이 같은 장에 연속되면 **한 슬라이드에 병합**한다 — 절 제목을 소제목으로
  스택하고, CONTENTS 는 병합된 절 모두 같은 슬라이드 번호를 가리킨다. 분량이 본문
  예산을 넘으면 절 경계에서만 나눈다. 절마다 거의 빈 슬라이드가 생기는 낭비를 막기
  위함이다. (번들 빌더 내장 — 템플릿 서식 복제 경로에서도 동일 적용)
- **표 높이**: 쪽 나눔 전에 표 높이를 추정한다. PowerPoint 가 있는 PC 에서는 셀 줄 수를
  글꼴 파일로 재서(한글은 글자마다, 영문은 단어째 줄바꿈) 쪽을 채우고, 빌드 끝에 표가 있는
  쪽을 **실제 렌더로 검사**해(`scripts/check_layout.ps1` — 표와 아래 내용의 겹침, 본문 하한
  넘침) 문제가 있으면 넉넉한 추정(`--table-estimate safe`)으로 스스로 다시 짓는다.
  PowerPoint·글꼴 파일·Pillow 가 없으면 처음부터 넉넉한 추정이다(겹침 없음, 대신 표 쪽
  아래에 여백). 보정 근거는 `tools/README.md`.

### 템플릿 모드 (사용자 pptx 템플릿 — `--template`)

사용자가 쓰는 매뉴얼 pptx 템플릿이 있으면 **그 모양 그대로** 짓는다:
`python scripts/build_pptx.py --draft … --out … --template <템플릿.pptx | 등록 이름 | default>`

- **등록부**: 한 번 쓴 템플릿은 빌드에 성공하면 사용자 폴더의 등록부
  (`~/.claude/manual-gen/templates.json`, skill 저장소 밖)에 이름(기본: 파일 이름)으로
  등록되고, 첫 등록이면 기본 템플릿이 된다. `scripts/template_registry.py` 로 관리한다 —
  `list`(`*` = 기본) · `add <경로> [--name 이름] [--default]` · `default <이름>` ·
  `remove <이름>` · `resolve [이름]`. 템플릿 파일을 옮겼으면 같은 이름으로 `add` 하면
  경로가 갱신된다. 등록돼 있어도 실행마다 확인 표에서 사용자가 확인한 뒤 적용한다.

- **나눔**: 템플릿에서 가져오는 것 = **크롬**(표지·목차·본문 머리/꼬리·장/절 제목 상자·
  글꼴·색·표본 쪽 장식). 번들이 그리는 것 = **본문**(캡처 검은 테두리·균일 폭 6.4in·
  긴 캡처 타일 분할·표 자동 분할·배지 배분·개요 병합·검증 게이트). 슬라이드를 통째로
  복제하던 방식의 디자인 깨짐(제목 겹침·목차 붕괴·기하 초기화)이 구조적으로 생기지 않는다.
- **템플릿 요건**: 세로 A4(7.5x10.83in) 또는 가로 16:9(13.33x7.5in). 첫 슬라이드 = 표지
  (시스템명은 제목 자리표시자), 목차 레이아웃('목차'/'CONTENTS' 글자와 'CHAPTER 01' 라벨
  자리), 본문 표본 슬라이드 1장('01. 장 제목'·'1.1 절 제목' 글상자). 간지 레이아웃은 쓰지
  않는다 — 장이 바뀌는 쪽의 머리 장 제목이 간지 역할을 한다.
- **분석·검토**: 처음 쓰는 템플릿은 분석 결과(매니페스트)를 사용자 로컬
  `~/.claude/manual-gen/templates/<이름>-<해시>.json` 에 저장하고 요약을 출력한다
  (`python scripts/analyze_template.py <템플릿.pptx>` 로 미리 볼 수 있다). 휴리스틱이므로
  **처음 한 번은 요약을 사용자와 검토**하고, 틀린 자리는 그 JSON 을 고친다. 템플릿 파일이
  바뀌면 해시가 달라져 자동으로 다시 분석한다(`--template-refresh` 로 강제). 매니페스트에는
  개인 경로·표본 문구가 담기므로 skill 저장소 밖에 둔다.
- **채우는 자리**: 표지 — 시스템명·매뉴얼 구분·대상·연도·부제(영문 부제 자리에는
  버전·날짜). 목차 — 템플릿 목차 자리의 글꼴·크기·색·줄 간격·하위 절 들여쓰기·쪽 번호
  정렬을 따른다. 본문 — 러닝헤더·꼬리 장 표기('CHAPTER 1. 장 제목')·쪽 번호를 채우고,
  장·절 제목은 표본 슬라이드의 상자를 복제해 글자만 바꾼다. 표본 슬라이드에만 그려진
  장식(선·도형·로고 그림)은 본문·목차 항목과 겹치지 않는 것만 쪽마다 옮긴다.
- **원본 보호·잔존 게이트**: 템플릿 파일은 읽기만 한다. 산출물(슬라이드·레이아웃·
  마스터·노트)에 템플릿 표본 문구(표본 시스템명·영문 부제 등)가 남으면 빌드가 ERROR 로
  멈춘다. 비어 있는 자리표시자는 지워 편집 화면에도 안내문이 남지 않게 한다.
- **본문 영역**: 템플릿 머리(장·절 제목)와 꼬리 선 사이로 본문 영역을 옮긴다. 캡처 폭
  6.4in(일관성 앵커)은 그대로이므로, 머리가 높은 템플릿은 쪽당 본문이 줄어 절 분할이
  조금 늘 수 있다(본문 문단은 기본 테마와 동일).
- **한계**: 템플릿 글꼴은 빌드·열람 PC 에 설치돼 있어야 같은 모양이 된다(PDF 는 빌드
  PC 기준으로 글꼴을 넣는다). 표본 슬라이드의 차트·SmartArt 는 옮기지 않는다. 지원 크기
  밖이거나 본문 표본이 없는 템플릿은 분석이 실패한다 — 이때는 기본 테마로 짓고, 사용자가
  명시 요구하면 아래 '참고 템플릿 서식 복제(예외 경로)'.

### 화면 슬라이드 레이아웃 (신규 생성 시)

```
┌─────────────────────────────────────────────────┐
│ 시스템명  관리자 매뉴얼            03  화면 및 기능 설명 │ ← 러닝헤더(좌: 문서명, 우: 장)
├─────────────────────────────────────────────────┤ ← 가는 강조선
│ 3.2.1   관리자 (1/2)                              │ ← 절 번호(강조색) + 절 제목
│ 화면 개요 1~2문장 (14pt)                          │
│                                                   │
│ ┌───────────────────────────┐  ① 설명 …          │
│ │                           │  ② 설명 …          │
│ │   스크린샷(annotated)      │  ③ 설명 …          │ ← 좌: 이미지(높이 우선 맞춤)
│ │                           │  ※ 주의 …          │    우: 번호별 설명(12pt)
│ └───────────────────────────┘                     │
│  [사진 N] 화면명 (9pt, 이미지 하단)                │
├─────────────────────────────────────────────────┤ ← 가는 선
│                                             05   │ ← 쪽 번호(두 자리)
└─────────────────────────────────────────────────┘
```

- 이미지가 가로로 긴 화면(목록 위주)은 상(이미지)/하(설명) 배치로 전환한다.
- **스크린샷 고정 프레임(폭 = 일관성 앵커)**: 모든 화면 슬라이드에서 이미지는 **동일
  렌더 폭**으로 들어간다(세로형 전폭 6.4in) — 폭이 매뉴얼 일관성의 앵커다.
  높이는 캡처 비율을 따라 자연히 달라지되 폭은 절대 줄이지 않는다. 캡션 위치도 프레임
  하단에 고정한다. (번들 빌더 내장 — 전용 skill 경로에서도 이 요구를 명시적으로 전달할 것)
- **세로로 긴 캡처 = 타일 분할(폭 축소 금지)**: 이미지 비율(가로/세로)이 세로형 1.123
  (=6.4/5.7) 미만이면, 폭을 줄이는 대신 **표준 비율 밴드 N장으로
  자동 분할**해 각 밴드를 전폭으로 렌더한다(`(1/N)(2/N)` 캡션, 항목은 밴드별 배분).
  절단선은 배경 여백 행에 스냅해 표 행·카드가 잘리지 않는다. **논리 분할(기능 경계로
  개별 캡처)이 품질상 우선**이고 자동 타일은 풀페이지만 있을 때의 폴백이다(live-capture.md).
  self_check 가 세로형 렌더 폭 편차(>3%)·축소를 조립 시점에 경고한다.
- **스크린샷 테두리**: 모든 스크린샷에 검은색 실선 테두리(두께 기본값 0.75pt, 그림자
  없음)를 적용한다 — 흰 배경 캡처와 슬라이드의 경계를 살리기 위함이다.
  (번들 빌더 내장 — **템플릿 서식 복제 경로에서도 동일 적용**: 템플릿에 선례
  이미지가 없어도 이 규격을 따른다)
- 표지: 테마 색의 기하 도형 구성 + 대상 알약 라벨 + 시스템명(강조색) + **매뉴얼 구분**
  (크게) + 버전·날짜. 매뉴얼 구분은 `--cover-label` → 원고 제목("관리자 매뉴얼 —
  시스템명") → 대상(관리자용 → 관리자 매뉴얼) 순으로 정하고, 같은 문구가 본문 쪽
  러닝헤더에도 쓰인다. 장 간지: CHAPTER 라벨 + 큰 장 번호 + 장 제목 + 그 장의 절 목록.
- 목차: **모든 장·절을 나열**하고 각 항목에 해당 슬라이드 번호를 표기한다. 좌측에
  "목차", 우측에 장 블록(CHAPTER 라벨·장 제목·쪽)과 절(하위 절은 들여쓰기). 장
  중간에서 쪽·열이 바뀌면 새 쪽·열 맨 위에 "계속" 머리를 다시 단다.
  생성 마지막에 실제 번호로 갱신한다(분할 슬라이드는 첫 장 기준).
- **페이지 번호 정책: PPT 슬라이드 순번으로 고정한다** (표지 제외 전 슬라이드 우하단).
  콘텐츠만 세는 별도 연번은 목차 참조와 어긋나므로 쓰지 않는다.
- 본문 텍스트 상자는 왼쪽 정렬을 기본으로 한다(양쪽 정렬은 문장부호 고아 줄을 만든다).

### 참고 템플릿 서식 복제 (예외 경로 — 명시 요구 시에만)

**사용자 템플릿의 기본 경로는 위 '템플릿 모드'(`--template`)다.** 수작업 서식 복제는
레이아웃 상속·placeholder 기하·폰트 상속에서 의도와 다른 형태(제목 겹침·목차 붕괴·기하
초기화)가 자주 발생하고 번들 규격(테두리·타일·병합·캡션)이 자동 적용되지 않는다 —
템플릿 모드가 분석하지 못하는 템플릿을 사용자가 "서식 그대로" 쓰기를 명시 요구한
경우에만 이 한계를 고지하고 진행한다.
조직의 기존 매뉴얼과 형식을 일치시키는 것이 목적이므로, 새 레이아웃을 만들지 말고
템플릿의 서식을 그대로 복제한다:

1. pptx skill의 편집 워크플로로 템플릿을 unpack한다.
2. 슬라이드 유형을 식별한다: 표지 / CONTENTS / 장 간지 / **완성도 높은 화면 슬라이드 1장**(서식 원본).
3. 화면 슬라이드 서식 원본을 화면 수만큼 복제하고, 텍스트(절 번호·라벨, 개요, 번호별
   설명, 캡션)와 이미지(스크린샷)만 교체한다. 번호 배지가 템플릿에 도형으로 있으면
   그 도형을 재배치해 쓰고, annotate_screenshot.py 합성은 생략한다(이중 배지 방지).
   삽입하는 모든 스크린샷에 위 규격의 검은색 실선 테두리를 적용한다(템플릿에 이미지
   선례가 없어도 생략 금지).
4. CONTENTS의 절 목록·페이지 번호를 실제 구성에 맞게 갱신한다.
5. 템플릿에 있던 예시 내용이 남지 않았는지 전수 확인한다(placeholder 텍스트 grep).

### 검수 (두 형식 공통) — 기계 검증 우선

텍스트 추출본으로 grep·카운트 검증을 먼저 수행한다 (번들 빌더는 일부를 자체 수행):

- **마크다운 잔재**: `**`, `![` 패턴 잔존 여부
- **미확정 마킹**: `확인 필요`, `확정 전`, `TBD`, `미정` 잔존 여부
- **pptx 분할**: 슬라이드별 설명 항목(•/①) 수를 세어 6개 초과가 없는지
- **목차 대조**: CONTENTS(또는 TOC)에 본문의 모든 절이 나열되고 번호가 실제 슬라이드
  번호(또는 페이지)와 일치하는지

이후 시각 검사: 이미지 누락/깨짐, 요소 겹침, 캡션-사진 번호 대응, 한글 깨짐,
문장부호 고아 줄. **pptx 렌더는 번들 스크립트로 수행한다** (즉석 COM 코드 자작 금지):

```
powershell -ExecutionPolicy Bypass -File scripts/export_slides.ps1 `
  -Path <문서.pptx> [-OutDir manual-work\render-check] [-Width 1200]
```

PowerPoint COM 으로 슬라이드별 PNG 를 뽑고(문서를 열어 둔 상태여도 ReadOnly 로 동작),
PowerPoint 가 없으면 LibreOffice(soffice) PDF 변환으로 폴백한다. 표지·목차·대표 화면
슬라이드 3~5장을 열어 확인한다. 전용 skill 경로면 그 skill의 QA 절차(렌더 후 육안
검사)를 수행한다.
